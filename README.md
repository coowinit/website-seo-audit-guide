# Website SEO Audit Guide

网站 SEO 排查与优化操作指南。面向 B2B 网站技术维护及 SEO 协同工作，以“检查 → 证据 → 判断 → 整改 → 验收”为主线。

## v1.1 功能

- 10 个章节、25 个操作检查项，涵盖访问、索引、Canonical、页面标题、性能、内容、链接与转化。
- 各检查项包含工具、操作步骤、合格判断、常见误判、整改方式和验收建议。
- 章节导航、全站搜索、优先级筛选、检查进度（浏览器 localStorage）、深浅主题、打印、响应式布局。
- Screaming Frog 实战专题新增 8 个检查项目与 3 张示例截图，涵盖 Dashboard、Canonical、H1/H2、JavaScript 渲染及证据导出。
- 纯静态 HTML/CSS/JavaScript 和 JSON，无数据库或打包工具。

## 维护规范

- `data/sections.json` 定义章节；`data/checks.json` 定义检查项目。
- `checks.json` 的 `id` 必须唯一且稳定，变更 ID 会让用户保存在本地的完成进度失效。
- 每一条检查项尽量保留：检查目标、操作、合格判断、误判提醒、整改和验收。
- 外部链接引用官方文档优先，定期复核；不把工具警告当成真实故障。
- 本项目的案例属于方法示例，不构成对具体网站当前情况的持续监控。

## 后续路线图

> 当前稳定基线：**v1.1.0**（SEO 操作指南 + Screaming Frog 实战）。以下均为**规划中，尚未开发**的候选内容，后续按实际使用需求逐步推进，不预设完成时间。

### v1.2.0 — 审计记录与数据导出（下一阶段）

**目标：** 从“知道怎样检查”升级到“能记录不同网站的实际检查结果”，优先解决现有勾选状态不区分网站的问题。

- **按网站管理记录：** 以规范化域名标识网站；按审计日期或审计批次建立记录，避免不同网站的进度混用。
- **检查结果状态：** 以“未检查 / 正常 / 发现问题 / 待核实”代替单一的“已完成”勾选；状态与操作是否完成分开理解。
- **问题记录字段：** 保存检查项 ID、受影响 URL、问题描述、证据来源、证据日期、优先级、整改措施和验收状态；可选记录责任人。
- **数据导出与恢复：** JSON 用于完整备份与导入，CSV 用于整改清单和表格分析；导入时检查格式与版本，避免覆盖错误的数据。
- **兼容已有进度：** 保留现有 `checks.json` 项目 ID，并考虑将 v1.1 的 localStorage 勾选记录迁移为旧版检查进度，不擅自判断为“正常”。

**验收重点：** 不同网站记录互不干扰；刷新页面数据保留；JSON 导出再导入后记录一致；CSV 可正常打开；空数据、异常数据和重复导入有明确处理。

### v1.3.0 — 标准化 SEO 审计报告

**目标：** 从记录中生成适合内部汇报、整改协作与留档的报告。

- 提供“总体结论 → 核心问题 → SEO 分类检查 → 整改优先级 → 验收计划”的固定报告结构。
- 区分**已确认问题、疑似异常、待验证**，并标明数据来源和审计范围，不把 Semrush 估算当作 GSC/GA4 的真实数据。
- 支持按网站和批次汇总，避免同一问题在多份章节中重复出现。
- 优先实现独立、可打印的 HTML 报告，通过浏览器“打印 / 另存为 PDF”导出；是否需要原生 Word（DOCX）另行评估，避免增加复杂依赖。
- 保留检查记录与报告的关联，便于修复前后复查。

**验收重点：** 报告适合 A4 打印；无证据的结论不自动升级为故障；导出内容与记录一致；报告不泄露未授权客户信息。

### v1.4.0 — SEO 实战案例库

**目标：** 把重复出现的排查问题沉淀为可检索、可复用的方法，而不是持续堆积一次性报告。

- 先整理通用案例：Canonical 与重定向不一致、H1 多次使用、robots 阻断 JS 资源、Sitemap 异常、移动端 LCP 偏高等。
- 以“背景 → 观察证据 → 判断与误判 → 处理方案 → 验收结果 → 参考资料”的统一格式展示。
- Roshan、Evodek 等历史排查资料只作为**候选案例来源**；公开前必须核实披露权限、移除敏感信息，并避免将旧截图视为网站当前状态。
- 提供按 SEO 类别、问题类型和工具查询案例的入口；优先复用现有 JSON 驱动架构。

**验收重点：** 每个案例都有明确适用边界和证据日期；截图、域名及第三方软件资料符合公开要求；能从检查项快速找到关联案例。

### 长期候选方向（暂不纳入近期开发）

- Google Search Console 数据解读、关键词与内容矩阵、内部链接和转化分析专题。
- JavaScript SEO、WordPress、多语言 hreflang、结构化数据等进阶内容。
- 必要时引入 GSC/GA4 数据导入或辅助分析，但先明确数据权限、隐私和维护成本。
- GEO / AI 搜索内容的可验证评估方法。

### 实施原则

1. **先稳定再扩展：** 维护现有 UI、章节导航和静态架构，不因增加功能而全面重构。
2. **内容与功能分离：** 检查知识继续由 JSON 管理，业务记录与指南内容使用独立数据结构。
3. **优先本地、可备份：** 初期不引入 PHP、数据库或账号系统；浏览器 localStorage 不是长期可靠备份，重要审计记录应定期导出 JSON。
4. **证据优先：** 工具告警不等于真实 SEO 故障；记录事实、判断、假设和验收结果。
5. **隐私与授权：** 公开 GitHub Pages 不应存放客户真实私密审计记录；新增数据功能须确保默认不上传，截图需脱敏并检查授权。
6. **版本化迭代：** 每个阶段单独测试、更新 README 后再发布 Release；未实现功能在文档中始终标注为规划内容。
